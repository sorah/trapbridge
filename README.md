# Trapbridge: SNMP traps to Amazon EventBridge

Trapbridge is a daemon that receives SNMP traps and informs, decodes them, and forwards each one to an Amazon EventBridge event bus as a JSON event. Rules on the bus can then route network events to Lambda, SNS, Step Functions, CloudWatch Logs, or anything else EventBridge targets.

OIDs are named from MIB data dumped to JSON ahead of time, so the daemon itself and its container image need neither net-snmp nor MIB files. The dump is generated by a `trapbridge mib-dump` subcommand, much like snmp_exporter's generator.

## Features

- SNMPv1 Trap-PDU, SNMPv2c Trap and InformRequest (acknowledged), and SNMPv3 Trap with USM authentication and privacy (MD5/SHA-1/SHA-2, DES/AES)
- MIB names for the trap OID and every varbind (`IF-MIB::ifOperStatus`, instance `3`), enumeration labels, BITS labels, and values formatted by DISPLAY-HINT or an explicit format (MAC address, DateAndTime, InetAddress)
- SNMPv1 traps are translated to `snmpTrapOID` per RFC 3584, so v1 and v2c `linkDown` look the same to a rule
- Batched `PutEvents` with one retry of failed entries
- `--dry-run` prints events to stdout instead of sending them
- Optional HTTP listener with `/healthz` and Prometheus `/metrics`

## Installation

### Container image

```
docker run -p 162:162/udp -e TRAPBRIDGE_EVENT_BUS=default ghcr.io/sorah/trapbridge:latest
```

The image runs `trapbridge server`. AWS credentials come from the usual SDK chain (environment, ECS task role, instance profile, and so on).

### Release binaries

Linux (musl) binaries for x86_64 and aarch64 are attached to [GitHub releases](https://github.com/sorah/trapbridge/releases), with build provenance attestations:

```
gh attestation verify trapbridge-x86_64-unknown-linux-musl.tar.gz --repo sorah/trapbridge
```

### Cargo

```
cargo install trapbridge
```

`mib-dump` is behind the `mibs` feature because it links libnetsnmp. Install the net-snmp development package (`libsnmp-dev` on Debian/Ubuntu, `net-snmp` on Arch Linux) first:

```
cargo install trapbridge --features mibs
```

## Usage

### 1. Dump MIBs to JSON

On a machine with net-snmp and the MIBs you need:

```
trapbridge mib-dump --config mib-dump.json -o mibs.json
```

```jsonc
// mib-dump.json
{
  "mib_dirs": ["/usr/share/snmp/mibs", "./vendor-mibs"], // default: net-snmp's search path, or MIBDIRS
  "modules": ["SNMPv2-MIB", "IF-MIB"],                  // default: every module found
  "include": [                                          // subtrees to export; default: every notification
    "SNMPv2-MIB::snmpTraps",
    "IF-MIB::linkDown",
    "IF-MIB::ifPhysAddress",
    "1.3.6.1.4.1.9.9.43"
  ],
  "overrides": {
    "IF-MIB::ifPhysAddress": { "type": "PhysAddress48" }, // force a value format
    "ifAlias": { "display_hint": "255a" },                // replace the DISPLAY-HINT
    "IF-MIB::ifAdminStatus": { "name": "ifAdminState" },  // rename
    "noisyObject": { "ignore": true }                     // leave out
  }
}
```

- `include` takes names (`MODULE::name` or a bare name) or numeric OIDs. Every node under each root is exported. The objects that a notification's `OBJECTS` (or SMIv1 `VARIABLES`) clause refers to are exported too, even when they live outside the subtree.
- `type` in `overrides` is one of:
  - `DisplayString`
  - `OctetString` (hex)
  - `PhysAddress48`
  - `InetAddress`
  - `DateAndTime`

  Objects with the `DateAndTime` and `InetAddress` textual conventions get the matching format without an override.
- An `include` or `overrides` key that matches no node is an error.
- net-snmp parse errors fail the dump unless `--fail-on-parse-errors=false` is given.

See [mib-dump.sample.json](./mib-dump.sample.json) to start.

### 2. Run the server

```
$ trapbridge server --listen 0.0.0.0:1162 --community public --mib-json mibs.json --dry-run
$ snmptrap -v2c -c public 127.0.0.1:1162 '' IF-MIB::linkDown IF-MIB::ifIndex.3 i 3 IF-MIB::ifOperStatus.3 i 2
```

This prints:

```json
{"version":"v2c","source":{"address":"127.0.0.1","port":45562},"pdu_type":"trap","request_id":112714977,"uptime":232930723,"trap":{"oid":"1.3.6.1.6.3.1.1.5.3","name":"IF-MIB::linkDown"},"varbinds":[{"oid":"1.3.6.1.2.1.2.2.1.1.3","name":"IF-MIB::ifIndex","instance":"3","type":"integer","value":3},{"oid":"1.3.6.1.2.1.2.2.1.8.3","name":"IF-MIB::ifOperStatus","instance":"3","type":"integer","value":2,"value_name":"down"}]}
```

Replace `--dry-run` with `--event-bus NAME_OR_ARN` to send the events to EventBridge.

### 3. Route events

```json
{
  "source": ["trapbridge.0w0.co"],
  "detail-type": ["SNMP Trap"],
  "detail": {
    "trap": { "name": ["IF-MIB::linkDown"] }
  }
}
```

## Configuration

### Server flags

| Flag | Environment variable | Default | |
|---|---|---|---|
| `--listen` | `TRAPBRIDGE_LISTEN` | `0.0.0.0:162` | UDP addresses, repeatable or comma-separated |
| `--event-bus` | `TRAPBRIDGE_EVENT_BUS` | (required unless `--dry-run`) | Event bus name or ARN |
| `--event-source` | `TRAPBRIDGE_EVENT_SOURCE` | `trapbridge.0w0.co` | Event `source` |
| `--detail-type` | `TRAPBRIDGE_DETAIL_TYPE` | `SNMP Trap` | Event `detail-type` |
| `--mib-json` | `TRAPBRIDGE_MIB_JSON` | none | `mib-dump` outputs, repeatable or comma-separated. Later files win on duplicate OIDs |
| `--community` | `TRAPBRIDGE_COMMUNITIES` | none | Accepted v1/v2c communities. Any community is accepted when none is set here or in `--config` |
| `--config` | `TRAPBRIDGE_CONFIG` | none | JSON configuration file, below |
| `--dry-run` | `TRAPBRIDGE_DRY_RUN` | off | Print events to stdout as JSON lines |
| `--http-listen` | `TRAPBRIDGE_HTTP_LISTEN` | none (disabled) | TCP address for `/healthz` and `/metrics`, e.g. `0.0.0.0:9162` |
| `--log-json` | `TRAPBRIDGE_LOG_JSON` | off | JSON logs on stderr |

Log verbosity is set by `TRAPBRIDGE_LOG` or `RUST_LOG` (default `info`). Use `debug` to log every received trap.

### Configuration file

```jsonc
// config.json
{
  "communities": ["public"],
  "v3_users": [
    {
      "username": "switch01",
      "engine_id": "80001f8880aabbccdd",  // sender's engine ID, hex
      "auth_protocol": "sha256",           // md5, sha1, sha224, sha256, sha384, sha512
      "auth_password": "change-me-auth",
      "priv_protocol": "aes128",           // des, aes128, aes192, aes256
      "priv_password": "change-me-priv"
    },
    {
      "username": "fleet",                 // no engine_id: accepted from any engine
      "auth_protocol": "sha1",
      "auth_password": "change-me-auth"
    }
  ]
}
```

- Omit `auth_*` for noAuthNoPriv, and `priv_*` for authNoPriv.
- `key_extension` (`blumenthal` or `reeder`) is needed when AES-192/256 is combined with an auth protocol whose digest is too short for the key.

See [config.sample.json](./config.sample.json).

### Metrics

With `--http-listen`, `GET /healthz` returns `ok` and `GET /metrics` returns counters in OpenMetrics text format:

| Metric | Labels | |
|---|---|---|
| `trapbridge_received_total` | `version`, `pdu_type` | Messages decoded into an event |
| `trapbridge_dropped_total` | `reason`: `parse`, `community`, `usm`, `unsupported` | Messages dropped before becoming an event |
| `trapbridge_events_put_total` | | Events accepted by `PutEvents`, or printed in `--dry-run` |
| `trapbridge_events_failed_total` | `error_code` | Events that failed after the retry (EventBridge error code), or were dropped as `TooLarge` or `Serialize` |

### IAM policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "events:PutEvents",
      "Resource": "arn:aws:events:us-east-1:123456789012:event-bus/default"

  ]
}
```

## Event format

Each trap becomes one event. The event time is when the trap was received; the trap itself is the `detail`:

| Field | |
|---|---|
| `version` | `v1`, `v2c` or `v3` |
| `source` | Sender address and port, as seen by trapbridge |
| `pdu_type` | `trap` or `inform` |
| `request_id` | PDU request-id (absent for v1) |
| `uptime` | `sysUpTime.0`, or the v1 time-stamp, in hundredths of a second |
| `trap` | `snmpTrapOID.0`: `oid`, and `name` when known |
| `varbinds[]` | Remaining varbinds, described below |
| `v1` | v1 only: `enterprise`, `agent_address`, `generic_trap`, `specific_trap` |
| `v3` | v3 only: `username`, `engine_id` (hex) |

Each entry in `varbinds` has these fields:
- `oid`
- `name` and `instance`: the deepest known MIB node and the sub-identifiers after it
- `type`: `integer`, `octet_string`, `object_identifier`, `ip_address`, `counter32`, `gauge32`, `timeticks`, `counter64`, `opaque`, `null`, ...
- `value`: a number, or a string for octet strings, OIDs and addresses
- `value_hex`: raw octets
- `value_name`: enumeration label, or the name of an OID value
- `bits`: BITS labels
- `units`

The community string is not included.

## How it works

1. A UDP socket per `--listen` address receives datagrams.
2. v1/v2c messages are checked against the accepted communities. v3 messages are matched to a configured user by (engine ID, username), then authenticated and decrypted.
3. Informs (v2c) are acknowledged with a Response PDU before the event is sent.
4. The PDU is converted to the event above, using the MIB JSON for names and formatting.
5. Events are batched (up to 10 per `PutEvents`, or 200 ms) and sent. Entries EventBridge rejects are retried once, then logged.
6. On SIGINT/SIGTERM, listeners stop and queued events are flushed.

Malformed messages, unknown communities and USM failures are logged at warn level with the sender address and dropped.

## Caveats

- SNMPv3 Informs are not supported, because acknowledging them requires trapbridge to be the authoritative engine (engine discovery and Reports). They are logged and dropped. v3 Traps work because the sender is authoritative.
- A v3 user configured without `engine_id` is accepted from any engine ID. Keys are localized on the first message from each new engine ID, which costs CPU, and up to 4096 learned engine IDs are kept. Prefer pinning `engine_id` when the senders are known.
- There is no deduplication. A retransmitted Inform whose acknowledgement was lost produces a second event.
- Port 162 is privileged. Outside a container, run with `CAP_NET_BIND_SERVICE` (e.g. `AmbientCapabilities=CAP_NET_BIND_SERVICE` in a systemd unit), or listen on a high port.
- Events over EventBridge's 256 KB entry limit are logged and dropped.

cargo test --all-features   # needs net-snmp headers for the mibs feature

### Implementation notes

- aws-sdk-rust (`aws-config`, `aws-sdk-eventbridge`) on tokio
- snmp2 with the `crypto-rust` feature for decoding. The `mibs` feature (opt-in) adds snmp2's `mibs` feature, which provides net-snmp initialization, and direct net-snmp FFI for walking the MIB tree.
- clap derive with `env` for configuration. Options too complex for flags are loaded from JSON files with serde_json.
- tracing and tracing-subscriber for logging
- axum and prometheus-client for the HTTP listener and metrics
- The MIB-to-JSON dump follows [snmp_exporter's generator](https://github.com/prometheus/snmp_exporter/tree/main/generator), keeping MIB handling out of the container image.
